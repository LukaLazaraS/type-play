## Decisions on the way

- 06:10 Worktree `night-perf` created with EnterWorktree (origin/main == main == b95bd52). The 11-01 research doc is
  untracked in the main checkout; the night's research refers to it there.
- 06:20 Research delegated to a background agent (sources + quotes); meanwhile prototypes on copies of the showcase
  games in the job's tmp folder (`$CLAUDE_JOB_DIR/tmp/games`, never the main checkout's output folders).
- Headless Godot facts (probe): `_draw()` and the `draw` signal run headless, so redraws per frame are countable;
  `RenderingServer.frame_post_draw` never fires headless (helpers must skip baking there); `--fixed-fps` runs unsynced.
- Stress measurement prototype (`test/helpers.gd` `measure()`): show-td and show-td-polished both measure ~12-15 ms a
  frame and 214 custom redraws a frame headless (enemy.gd 119, tower.gd 75): the polished one bakes only with a real
  renderer and falls back to redrawing headless. So the shared-looks helper must keep the same structure headless.
- Start-freeze prototype (WebGL probe in web.mjs, cold profile, 4x CPU, SwiftShader): show-runner-polished and
  show-3d-polished each link 1 shader program after play starts; all showcase games show ~1 s at the tap (level build
  + SwiftShader read-back). 3D frame times in SwiftShader are meaningless (median 224 ms), so the budget is the
  number of programs linked after play starts; frame times are reported, not failed (seen: one run 49 ms worst, the
  same probe next run 1019 ms: shared-PC noise).
- `lib/looks.gd` (shared looks, flyweight) + `lib/warmup.gd` tested in the browser: 300 sprites fine; with the
  warm-up 0 programs after play starts, without it 1 (the first particle burst, 143 ms after the tap). A transparent
  SubViewport stores premultiplied colour (50% red read back as 0.5,0,0,0.5: muddy); fixed with a second pass that
  un-premultiplies (`blend_disabled` shader), read back 1.0,0,0,0.5, screenshot correct. No GPU read-back at all.
