**The builder** (`packages/agent`):
- `rules/FAST.md` (new, read on every build and change): draw each look once (`lib/looks.gd`), redraw only on change,
  draw calls, lists not searches, think a few times a second, nearby-only checks, pools and caps, a world that frees what
  is behind, 3D materials never switched in play, the warm-up, and the stress test (with an example). Every genre skill
  names its busiest moment and its cheap drawing; BASE, STEP and EDIT rules point to it; `GOTCHAS.md` lost the drawing
  lines it replaces.
- Template: `lib/looks.gd` (every look drawn once into one shared picture; sprites batch; `Looks.rect()` bars;
  straight colours, no GPU read-back), `lib/warmup.gd` (draws one of everything behind the title), at most 3 catch-up
  physics steps, `test/helpers.gd measure()`. run.mjs copies the helpers into every game on every run and adds the
  physics line to older games.
- `apps/games/play.html`: after the download it says "Preparing graphics (first time only)…" with a moving bar until
  the first frame (screenshot checked).

**The check** (`tools/check.mjs`, `tools/web.mjs`): runs the game's stress test headless (game code a frame, things
redrawn every frame, nodes growing) and again in a browser (draw calls); a cold browser at 4× slower CPU counts the
shaders compiled after the first tap, GPU read-backs, and the draw calls on the title and in play. Budgets: 4 ms game
code (scaled to the machine), 30 redraws, 300 draw calls (title, early play), 400 at the busiest moment, 0 compiles and
read-backs after the tap. New games (`TEMPLATE` 2) fail over budget; older games get notes, so testers' edits don't
suddenly fail. A full check takes ~1.5 min on a light 2D game, ~30-40 s more than before; heavier and 3D games longer.

## Answers (decided by Luka through HQ; no questions tonight)

- Code-drawn 2D art stays. Fix = draw each look once, reuse for every copy (flyweight); animate the picture (move, turn,
  scale, a few frames drawn at start); redraw only when a look really changes; live drawing every frame only for a few
  things (player, a health bar); first drawing behind the loading screen.
- Fast by how the code is written, at every level / point of progress / condition: a frame's cost must not grow with
  play time (shared looks, pools, caps, nearby-only checks, targets picked a few times a second). Plus a short automatic
  test on every build that jumps straight to the worst moment and measures for under a minute; a slow game goes back to
  the agent like a failed test. Must work for a 2-hour game too.
- Every game gets a warm-up: every material, effect, particle and text size drawn once behind the title/loading
  screen.
- Research first, with sources; write it up in docs/research/; turn it into the game agent's rules.
- Testers' games: fix live or as local copies, whichever is less work. A live update goes the project's standard way
  and keeps the previous build for rollback. Games only.
- Rules: worktree on a night branch, commits there fine; nothing merged/pushed to main, no deploy of site or server.
  CLAUDE.md rules (cpu.mjs, one hidden browser at a time, stop what you start, scripts/test-run.mjs). Another night
