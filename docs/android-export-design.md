# Android export: implementation spec (package 7)

Written 2026-10-18 from four research passes, three competing designs and two judges. The
robustness-first design won, built lean, with both judges' grafts; where the judges disagreed,
correctness and safety won. Sources: a **FACT** key (F12) or **ESTIMATE** key (E3) is an entry with its
URL and date, or its method, in `docs/research/android-export-2026.md`; Q5 is an open question there.
Nothing in `apps/`, `packages/` or `deploy/` was changed tonight: this is the plan the Builder implements.
**Built 2026-10-18 (server side; the web screens of §11 are next):** `apps/server/README.md` "Android export" is
the record of what exists and what differs from this spec; the WSL toolchain test's numbers are in §13 below and
in `docs/research/android-export-2026.md` E2/E3 (APK 5 s / AAB 36 s offline, 25.4 MB each, peak RSS 0.7 / 0.9 GB).

## 0. The shape, in ten lines

1. On a paid plan, an **Android** pill on the game page opens `/games/<id>/android`: an APK to install on your own phone and an AAB for Google Play, from any version of the game, signed with the user's own upload key. Free has no export; paid exports cost no credits (FACT F76, `docs/pricing.md`).
2. Godot never signs. The runner job exports an **unsigned** APK (prebuilt template, no Gradle) or AAB (Gradle, offline) in a scratch copy of the game at a pinned commit, inside the throwaway job home. `package/signed=false` skips apksigner; the Gradle path gets `perform_signing=false` (FACT F26, F4).
3. A `signer` sidecar (same image, no network, read-only root, no secrets) signs with apksigner (APK) or jarsigner (AAB) (FACT F46) and inspects the result. The api runs no JVM and still never runs anything inside a game folder.
4. One upload keystore per game, made by the signer with keytool, encrypted under `ANDROID_KEY_MASTER` (api.env only), stored as ciphertext in Postgres, downloadable by the owner. With Play App Signing it is only the upload key: Google holds the app key and a lost upload key is reset in Play Console (FACT F51).
5. One Android build at a time on the box, the project reserved while its build runs, hard timeouts at every step, every state change written to Postgres before it is announced on the existing event stream.
6. The server writes the Android preset itself and refuses to sign an output whose manifest differs from the request (package, version code, debuggable, permissions, target SDK, certificate): a prompt-injected export plugin fails the build instead of shipping.
7. The toolchain is pinned by hash and proven at image build: a `RUN --network=none` export of the blank template to APK and AAB must pass, or the deploy fails (like today's WebGL check, FACT F74).
8. Reproducible: a build = (the version's commit, the server's preset, a toolchain fingerprint). Files expire after 30 days and are rebuilt on demand.
9. No debug builds: the phone APK is the release build signed with the same key (Play refuses debuggable uploads, FACT F52; sideloaded builds must carry the user's key, not ours, under developer verification, FACT F67).
10. Deferred (section 15): the wizard with saved state, store pictures, the hosted privacy page, one-click upload.

## 1. Trust boundaries

| Piece | Has | Never has |
|---|---|---|
| runner job (uid 10001-10008, no internet, FACT F75) | the game at one commit (scratch copy), Godot, JDK + SDK read-only, a copy of the Gradle seed, the icon PNG the api passed in | keystore, password, ciphertext, master key, R2 keys. Its refusal regex gains `ANDROID_KEY_\w+\|GODOT_ANDROID_KEYSTORE_\w+\|SIGNER_\w+` (narrow: its own `ANDROID_HOME`, `JAVA_HOME` stay) |
| signer (uid 1000, own container, `network_mode: none`, `read_only`, tmpfs `/tmp`) | one keystore for seconds in its tmpfs, the unsigned file, JDK, build-tools, bundletool | network, DB, R2, master key, `/data`, game folders |
| api (uid 1000) | master key, DB, R2 keys | Godot, git, java, gradle; nothing executes inside a game folder |

Why Godot must not see the key: it passes the password on the command line to apksigner (`--ks-pass pass:`) and to gradlew (`-Prelease_keystore_password=`), readable from `/proc/<pid>/cmdline` by every process of that uid, and the job runs the game's own `@tool` scripts and any export plugin the agent wrote (FACT F26, F27; `apps/server/README.md`). The env-var route (F15) is readable by the same processes. So: unsigned export, sign elsewhere. The Android job has the same trust level as an agent run (Gradle executes build scripts; no worse than the agent's bash).

## 2. The image (`deploy/api/Dockerfile`, `deploy/api/compose.yaml`, `deploy/deploy.mjs`)

New stages before `COPY full/`, so BuildKit keeps them across deploys (FACT F44); `deploy.mjs api` copies a new static folder `deploy/api/android/` (seed preset, placeholder icons, `gradle.properties`, the offline init script) into the build context as `src/android/` next to the Dockerfile.
- `godot` stage: also unzip `templates/android_release.apk` and `templates/android_source.zip` from the same SHA-512-checked tpz (104,803,333 B and 214,418,211 B, FACT F6). Not `android_debug.apk` (no debug builds).
- `android-sdk` stage: `apt-get install openjdk-17-jdk-headless` (Debian bookworm 17.0.20.1, ~266 MB, FACT F34; Godot recommends 17, F1); `commandlinetools-linux-15859902_latest.zip` pinned by SHA-256 `4e4c464f…f583` (181.8 MB, FACT F36) into `/opt/android/sdk/cmdline-tools/latest`; `yes | sdkmanager --licenses`; versions **read from the template**: a shell step unzips `config.gradle` from `android_source.zip` and greps `buildTools` and `compileSdk` (36.1.0 and 36 for 4.7.2, FACT F2), then `sdkmanager --sdk_root=/opt/android/sdk "platform-tools" "build-tools;<bt>" "platforms;android-<sdk>"`. No NDK (Godot's release `.so` files are already stripped; AGP only warns without one: F7, F40, ESTIMATE E8) and no CMake; Godot itself checks only `java`, `platform-tools/adb` and `build-tools/<v>/apksigner` (FACT F12). bundletool jar from google/bundletool releases, pinned by SHA-256, a version at least two weeks old. Writes `/opt/android/TOOLCHAIN` = `godot4.7.2+agp8.6.1+gradle8.11.1+bt36.1.0+sdk36+jdk17+bundletool<v>`.
- `gradle-seed` stage (has internet at build time): one real `--import` then `--install-android-build-template --export-release Android` of `packages/agent/templates/blank` to AAB, with the seed preset and `GRADLE_USER_HOME=/opt/android/gradle-home` holding `gradle.properties` (`org.gradle.jvmargs=-Xmx1536m -XX:MaxMetaspaceSize=512m`, `org.gradle.daemon=false`, `org.gradle.workers.max=2`, `org.gradle.parallel=false`, `android.builder.sdkDownload=false`: the user-home file beats the template's `-Xmx4536m`, FACT F41, F3, F38) and `init.d/offline.init.gradle` (`gradle.startParameter.offline = true`, ESTIMATE E9; fallback: a patched `android_source.zip` whose `gradlew` appends `--offline`, via `gradle_build/android_source_template`, FACT F19). Then delete `daemon/`, `native/`, `*.lock` and the build output; `chmod -R a+rX`. Size 0.7-1.2 GB (ESTIMATE E4).
- `self-test` stage, `RUN --network=none`: from a copy of the seed, export the blank template to APK (prebuilt path) and AAB (Gradle) exactly as the runner will, then `aapt2 dump badging` / `bundletool dump manifest` must show target SDK ≥ 36 and `zipalign -c -P 16 4` / `bundletool dump config` must pass the 16 KB check (FACT F55, Q6). Any failure stops the image build, so the deploy fails, never a user's export. This settles Q1-Q3 at build time.
- Final stage: `COPY --from=android-sdk /opt/android /opt/android` (+ the JDK), `COPY android/ /opt/typeplay/android/`; `ENV JAVA_HOME=/usr/lib/jvm/java-17-openjdk-amd64 ANDROID_HOME=/opt/android/sdk ANDROID_BUILD_TOOLS=<bt> GRADLE_SEED=/opt/android/gradle-home BUNDLETOOL_JAR=/opt/android/bundletool.jar ANDROID_ICONS=/opt/typeplay/android/icons`; `mkdir -p /exports /run/typeplay-signer && chown 1000:1000` so the named volumes inherit that ownership (a non-root signer cannot chown a fresh volume).
- compose: new service `signer` (section 7); new volumes `exports` (api + signer only; the runner never mounts it) and `signer-socket`; api gets `SIGNER_SOCKET=/run/typeplay-signer/signer.sock`, `ANDROID_EXPORT=1`, `EXPORTS_DIR=/exports`, `MAX_ANDROID_BUILDS=1`, `ANDROID_BUILD_TIMEOUT_MIN=14`; `deploy.mjs`: `API_KEYS` gains `ANDROID_KEY_MASTER`, a new `android-key` command writes it into the root `.env` if absent (64 hex chars, prints only its length), and the deploy guard also refuses while `health.android.running > 0` (today only `health.runs`, FACT F76). Image growth +1.5-2.2 GB, first deploy +10-15 min (ESTIMATE E4); the 160 GB disk is fine.
- Godot version change (4.8.x): change `GODOT_VERSION` and the two hashes; the SDK versions, the seed and the self-test follow from the new template; every build row records `godotVersion` and `toolchain`; a rebuild of an old version runs on the new Godot in a scratch copy (import migrates), and a failed import is a `game` failure that sends the user to the chat.

## 3. The runner job `android` (`apps/server/runner/runner.mjs` + new `runner/android-prepare.mjs`, `runner/android-icons.gd`)

- Body: `{ kind: "android", project, args: ["--commit", <40 hex>, "--format", "apk"|"aab", "--package", p, "--version-code", n, "--version-name", s, "--app-name", s, "--orientation", "portrait"|"landscape", "--build-id", id], files: { "icon.png": <base64> } }`. The body cap rises from 256 KB to 2 MB (only the api can open the socket); `files` ≤ 1 entry ≤ 1 MB, written to `$HOME/in/` by root before the home is chowned. `LIMIT_MS.android = 15 min`; a kind-level semaphore (one `android` job at a time, like the hidden-browser lock) plus the existing per-project lock; `chownTree(dir)` as for `export`; `oom_score_adj 800` as today.
- Steps, all as the job user, in `$HOME/build`: (1) `git -c safe.directory=* -C <dir> archive --format=tar <commit> | tar -x -C $HOME/build/game` (committed files only: no `.godot/`, no `export/`, no hooks run; the agent's folder is not written). (2) `node android-prepare.mjs …`: deletes `android/` from the copy if the commit carried one (a planted `buildSrc/` would run inside Gradle); strips every `platform="Android"` preset from `export_presets.cfg` and appends the server's own (section 4); appends `[rendering] textures/vram_compression/import_etc2_astc=true` to the copy's `project.godot` (required for a command-line Android export on a Linux host, FACT F30; the blank template is left alone, so web checks stay as fast as today); writes `display/window/handheld/orientation` from `--orientation` (1 portrait, 0 landscape, FACT F23) only when the key is missing; writes `export/.gdignore`; makes the icons (section 5); for `aab` copies `$GRADLE_SEED` to `$HOME/.gradle`. (3) `godot --headless --path game --import`. (4) `godot --headless --path game [--install-android-build-template] --export-release Android $HOME/build/out/game.<ext>` (the install flag for AAB only: it unzips the template into the copy in the same run, FACT F5, F10, Q1; the copy dies with the home, so `.build_version` mismatches cannot happen). (5) `cp out/game.<ext> <dir>/export/android/unsigned-<buildId>.<ext>` (`export/` is gdignored and gitignored, FACT F76; the api reads it with `readGameFile`, symlink-safe, cap 300 MB, ESTIMATE E1 says ~27 MB + pack).
- Job env adds `JAVA_HOME`, `ANDROID_HOME` (Godot's editor settings default to them on a fresh home, so no `editor_settings-4.7.tres` is needed, FACT F11), `GRADLE_SEED`, `ANDROID_ICONS`, `GRADLE_USER_HOME=$HOME/.gradle`, `GRADLE_OPTS=-Dorg.gradle.daemon=false`. The preset says `runnable=false` so no adb poll thread starts (FACT F18).

## 4. The preset, filled per game (written by `android-prepare.mjs`; unit-tested as text)

```
[preset.N]  name="Android"  platform="Android"  runnable=false  export_filter="all_resources"
  exclude_filter="export/*,test/*,NOTES.md"  export_path="export/android/game.<ext>"
[preset.N.options]
  gradle_build/use_gradle_build=<true for aab, false for apk>  gradle_build/export_format=<1 aab, 0 apk>
  gradle_build/compress_native_libraries=false  architectures/arm64-v8a=true  (armeabi-v7a, x86, x86_64 false)
  package/unique_name="<packageName>"  package/name="<appName, " and \ escaped>"  package/signed=false
  version/code=<versionCode>  version/name="<versionName>"
  launcher_icons/main_192x192="res://export/icons/icon-192.png"  launcher_icons/adaptive_foreground_432x432="res://export/icons/fg-432.png"
  launcher_icons/adaptive_background_432x432="res://export/icons/bg-432.png"
  screen/immersive_mode=true  screen/edge_to_edge=false  user_data_backup/allow=false   (no permissions/*, empty keystore/*)
```
Keys and defaults: FACT F19. arm64-only satisfies Play's 64-bit rule (FACT F56); target 36 / min 24 are Godot's defaults and meet Play's 2026-08-31 rule (FACT F22, F54). Orientation is not a preset key (F23). Values: **packageName** default `app.typeplay.<slug>_<projectId>` (slug = the game name lowercased, non `[a-z0-9]` → `_`, cut to 20, prefixed `g` if it starts with a digit or is empty; the project id, not the user id, because a package name is per app and the id is already unique and short); rule `^[a-z][a-z0-9_]*(\.[a-z][a-z0-9_]*)+$`, 3-80 chars (FACT F58, F21); refuse the prefixes `com.example.`, `com.android.`, `android.`, `com.google.` (Play refuses `com.example`, community-reported, F58); unique across TypePlay. **appName** ≤ 30 (Play's listing limit, FACT F62), prefilled from the game name. **versionCode** = `AndroidApp.versionCode + 1` in the same transaction as the build row, never reused, gaps fine (FACT F57); **versionName** = `<versionN>.<versionCode>` (e.g. "7.3": version 7 of the game, build 3).

## 5. Icons (from the game's poster; FACT F24 sizes)

The api passes `files["icon.png"]`: the user's uploaded PNG when set (512×512+, ≤ 1 MB, PNG magic + IHDR parsed in Node, no image library), else the current build's poster (`export/screenshot-start.png`, the check's start-screen picture, FACT F76). `android-icons.gd` (`godot --headless --script … -- in.png outdir`, Godot's `Image` class) makes `icon-192.png` (a centre square crop, scaled), `fg-432.png` (the crop scaled to 66 % on a transparent 432 canvas: the safe zone) and `bg-432.png` (a solid colour sampled from the crop's edge). If there is no poster or the script fails, the placeholder set from `$ANDROID_ICONS` (a neutral controller glyph the Builder renders) is copied instead and the build row says `icon: "placeholder"`: the build never fails for lack of an icon. Q5 (icons from a gdignored folder) has the root-level fallback.

## 6. Keystore: make, store, use, hand over

- **Make** at setup (`POST /projects/:id/android`), per game (Google advises a unique key per app, FACT F51), by the signer's `keygen` op **before** the Prisma transaction: `keytool -genkeypair -keystore /tmp/<rand>/k.p12 -storetype PKCS12 -alias upload -keyalg RSA -keysize 2048 -validity 10000 -dname "CN=<app name>, O=TypePlay user" -storepass:env KS -keypass:env KS` (RSA ≥ 2048 and validity past 2033-10-22 are Play's rules, 10,000 days ≈ 27 years, FACT F51; `:env` keeps the password off the command line, FACT F50). Password: 32 random letters and digits made by the api (Godot's docs: letters and digits, store = key password, FACT F1), sent in the request body. The signer answers with the keystore bytes and the certificate SHA-256 (`keytool -exportcert` → sha256 in Node), then deletes its tmpfs file. ~3 KB, ~1 s (ESTIMATE E6).
- **Store**: `AndroidKey.blob` = `keyId(1) | nonce(12) | tag(16) | AES-256-GCM(JSON {p12: base64, password})`, AAD = projectId, key = `ANDROID_KEY_MASTER` (32 bytes as 64 hex chars; the api refuses to start with `ANDROID_EXPORT=1` and a missing or short key). Rotation designed, not built: `keyId` + `ANDROID_KEY_MASTER_PREV` + `npm run admin -- android rekey`. Never in a game folder, `export_presets.cfg`, `.godot/export_credentials.cfg`, a job's environment, or the exports volume.
- **Use**: decrypted only to put the bytes and password in the signer's `sign` request body; the signer writes them to its tmpfs (0600) for the seconds the tool runs and deletes them when the op answers, also on error.
- **Hand over**: `GET /projects/:id/android/key` → a zip: `<slug>-upload-key.jks` (PKCS12 inside; Android Studio, Gradle, Godot and Play read it) + `README.txt`: alias `upload`, the password, the SHA-256 fingerprint and: "This file signs the Android builds of this game. Google Play keeps the real signing key for you (Play App Signing); this one proves it is you who uploads. Keep it with the password: you need it to publish updates from your own computer, and anyone who has it can upload versions of your game. If you lose it, Google can replace it: Play Console > Protected with Play > Play Store protection > Manage Play app signing > Request upload key reset (the new key works about two days later). TypePlay keeps an encrypted copy so your builds here keep working." (FACT F51; two days = ESTIMATE E7.) Owner only, 5 downloads a day, `downloads` counted. Godot users: Project > Export > Android > Keystore: Release = this file, User = `upload`, Password = the one in the README.
- **Recovery**: user lost the file → download again; our DB lost (Supabase Free has no backups, FACT F72) → Play upload-key reset per game; master key lost → reset for every game (Luka keeps a second copy); breach of our copies → users reset; Play's app signing key is never affected (FACT F51).

## 7. The signer sidecar (`apps/server/signer/signer.mjs`; compose service `signer`)

Same image; `command: ["node","apps/server/signer/signer.mjs"]`; `user: "1000:1000"`; `network_mode: none`; `read_only: true` with `tmpfs: /tmp:size=512m`; `cap_drop: [ALL]`; `no-new-privileges`; `pids_limit: 256`; `mem_limit: 1g`; `cpus: 1.0`; volumes `exports:/exports` (rw) and `signer-socket:/run/typeplay-signer`; env only `JAVA_HOME`, `ANDROID_HOME`, `BUNDLETOOL_JAR`, `HOME=/tmp`, `JAVA_TOOL_OPTIONS=-Xmx512m` (the heap cap of every JVM it starts). Every tool is spawned with a minimal environment (PATH, JAVA_HOME, ANDROID_HOME, the password variable), never `process.env`, with a 2-minute timeout. Ops over `POST /jobs` on the socket (NDJSON answers, like the runner):
- `keygen { projectId, dname, password }` → `{ p12: base64, certSha256 }` (section 6).
- `sign { buildId, ext, p12: base64, password }`: APK `apksigner sign --ks k.p12 --ks-key-alias upload --ks-pass stdin --out /exports/<buildId>/signed.apk /exports/<buildId>/unsigned.apk` (password on stdin, FACT F47; Godot already 16 KB-aligned the APK in-process, FACT F25, and apksigner must run after alignment, F47); AAB `jarsigner -keystore k.p12 -storetype PKCS12 -storepass:env KS -keypass:env KS -signedjar signed.aab unsigned.aab upload` (apksigner cannot sign bundles, FACT F46; an unsigned export is required because jarsigner would add a second signer, F49).
- `inspect { buildId, ext }` → `inspect.json { package, versionCode, versionName, minSdk, targetSdk, debuggable, abis[], permissions[], certSha256, pageAlign16k, signed }` from `apksigner verify --print-certs` + `aapt2 dump badging` + `zipalign -c -P 16 4` (APK) or `jarsigner -verify -certs` + `bundletool dump manifest` + `bundletool dump config` (AAB) (FACT F47, F48, F55).
The api copies the unsigned file from the game folder into `/exports/<buildId>/` (owned 1000, 0750), calls `sign` then `inspect`, reads `signed.<ext>` and `inspect.json`, and deletes the folder. `src/android/inspect.ts` fails the build with `mismatch` unless package, versionCode and versionName equal the row, `debuggable` is false, `targetSdk ≥ 36`, `abis` = [arm64-v8a], `permissions` is empty, `certSha256` equals the key row, and `pageAlign16k` is true; a mismatch also logs a server warning (the tamper detector). Dev on Luka's PC: `SIGNER_SOCKET` unset → the same functions run in-process (needs a JDK 17 and build-tools; otherwise `features.android` is false). A zip-parser exploit in the signer would get one keystore for seconds and nothing else (no network, no DB, no master key); Play's upload-key reset is the backstop.

## 9. Contract (`packages/shared/src/index.ts`) and endpoints (`apps/server/src/android/`)

## 10. Queue, limits, timeouts, failures (`android.service.ts`, `errors.ts`)

- In-memory FIFO backed by rows (`queued` rows are the queue; on start, `running`/`signing` rows become `failed` `interrupted`, like runs, and `queued` rows re-enqueue). `MAX_ANDROID_BUILDS` = 1 (2 on the CPX42). A running build counts as **two run slots** in `reserve("run")` (`active.size + starting + 2 × androidActive ≥ maxRuns`) so one Gradle JVM plus one agent check stay under the runner's 5.5 GB cap (FACT F75; ESTIMATE E3). A queued build does not reserve the project; when its turn comes and the project has a run, it waits, re-checking every 5 s, at most 30 min, then fails `queue_full`.
- Transitions, each written then emitted: queued → running → signing → done | failed | cancelled; an hourly sweep marks `done` rows past `expiresAt` (30 days) as `expired` and deletes their files; files are kept only for the newest build of each format per game plus 30 days (ESTIMATE: 1,000 builds a month ≈ 30 GB on the 160 GB box, E5).
- Timeouts: api kills the job at `ANDROID_BUILD_TIMEOUT_MIN` = 14, the runner's 15 min is the backstop; signer ops 2 min; storing the file 3 tries. Caps (abuse guards, ESTIMATE): 1 build per project per minute, 10 per game per day, 30 per user per day.
- Failure codes → one plain sentence (Godot's strings are in FACT F12, F13, F27, F30): toolchain ("Android builds are broken on our side right now; we've been told. Nothing to do on your end." + server log + `/health` counter), game ("Your game's code has an error that stops the Android build. Ask for a fix in the chat: '<first error line>'", also appended to `errors.jsonl` so GOTCHAS can learn), gradle ("The packaging step failed. Try again; if it keeps failing, write to hello@typeplay.app with build <id>."), timeout, mismatch ("The build didn't come out the way we asked, so we didn't sign it. Try again from a version you trust."), sign, store, interrupted, queue_full. Full output in `data/logs/android-<buildId>.log`, last 4 KB (ANSI stripped) on the row behind "Details". `npm run admin -- android builds <projectId>` lists rows and logs; `-- android toolchain` prints the fingerprint.
