# Android export: research facts and sources (2026-10-18)

Companion to `docs/android-export-design.md`. Four research passes ran on the night of 2026-10-17/18
(Godot 4.7 headless export, Google Play rules, signing-key design, container and cost), read-only.
Every entry is **FACT** (source URL and the date it was read; "4.7.2-stable" means the source file at
that git tag on github.com/godotengine/godot, read 2026-10-18) or **ESTIMATE** (method given).
Community sources are marked as such: they are not Google or Godot pages. The design cites entries by
key (F12, E3, Q5).

- **F16** Keystore checks: "Either Debug Keystore, Debug User AND Debug Password settings must be configured OR none of them.", "Debug keystore not configured in the Editor Settings nor in the preset.", "Either Release Keystore, Release User AND Release Password settings must be configured OR none of them.", "Release keystore incorrectly configured in the export preset." Passwords typed into a preset land in `.godot/export_credentials.cfg` ("should generally not be committed"); `export_presets.cfg` "can be safely committed". export_plugin.cpp, 4.7.2-stable; https://docs.godotengine.org/en/stable/tutorials/export/exporting_projects.html (read 2026-10-18).

- **F18** With a runnable Android preset and adb present, the exporter starts a poll thread running `adb devices` every 3 s; `runnable=false` avoids it (`--export-release` does not need runnable). export_plugin.cpp, 4.7.2-stable.
- **F19** Android preset option keys and defaults (`get_export_options`): `custom_template/debug|release ""`; `gradle_build/use_gradle_build false`, `gradle_build/gradle_build_directory ""` (= res://android), `gradle_build/android_source_template ""`, `gradle_build/compress_native_libraries false`, `gradle_build/export_format 0` (0 APK, 1 AAB), `gradle_build/min_sdk ""` (24 default, 29 Vulkan), `gradle_build/target_sdk ""` (36), `gradle_build/custom_theme_attributes {}`; `architectures/armeabi-v7a false, arm64-v8a true, x86 false, x86_64 false`; `keystore/debug|debug_user|debug_password|release|release_user|release_password ""`; `version/code 1`, `version/name ""`; `package/unique_name "com.example.$genname"`, `package/name ""`, `package/signed true`, `package/app_category Game`, `package/retain_data_on_uninstall false`, `package/exclude_from_recents false`, `package/show_in_android_tv false`, `package/show_in_app_library true`, `package/show_as_launcher_app false`; `launcher_icons/main_192x192 ""`, `launcher_icons/adaptive_foreground_432x432 ""`, `launcher_icons/adaptive_background_432x432 ""`, `launcher_icons/adaptive_monochrome_432x432 ""`; `graphics/opengl_debug false`; `shader_baker/enabled false`; `xr_features/xr_mode 0`; `gesture/swipe_to_dismiss false`; `screen/immersive_mode true`, `screen/edge_to_edge false`, `screen/support_small|normal|large|xlarge true`, `screen/background_color Color()`; `splash_screen/*`; `user_data_backup/allow false`; `command_line/extra_args ""`; `permissions/custom_permissions []`; `permissions/<name> false` for every Android permission (e.g. `permissions/internet`). export_plugin.cpp, 4.7.2-stable.
- **F20** Class reference: `package/unique_name` is reverse-DNS, lowercase letters, digits, underscores and periods, each segment starting with a letter; `$genname` = lowercased project name with invalid characters stripped (or "noname"); changing it makes a new app and Play needs it globally unique; `version/code` must be incremented for every Play release; `version/name` falls back to `application/config/version`; keep `compress_native_libraries` false for Play; `launcher_icons/main_192x192` falls back to the project icon. https://docs.godotengine.org/en/stable/classes/class_editorexportplatformandroid.html (4.7 docs, read 2026-10-18).
- **F21** Package-name validation strings: "Invalid package name:" + "Package name is missing." / "Package segments must be of non-zero length." / "The package must have at least one '.' separator." / "A digit cannot be the first character in a package segment."; Godot has no rule against `com.example`. export_plugin.cpp, 4.7.2-stable.
- **F22** `DEFAULT_MIN_SDK_VERSION 24`, `DEFAULT_TARGET_SDK_VERSION 36`, `VULKAN_MIN_SDK_VERSION 29`; min/target are strings, empty = default, overrides need Gradle; "\"Min SDK\" cannot be lower than %d, which is the version needed by the Godot library." and "\"Target SDK\" version must be greater or equal to \"Min SDK\" version."; the GL Compatibility renderer is fine on Android. export_plugin.cpp, 4.7.2-stable.
- **F23** Screen orientation is not a preset key: Godot writes `display/window/handheld/orientation` (0 landscape, 1 portrait, 2/3 reverse, 4/5 sensor, 6 any) into the manifest's `screenOrientation`; `display/window/size/resizable` → `resizeableActivity`. The blank template sets 1. export_plugin.cpp `_fix_manifest`, 4.7.2-stable; https://docs.godotengine.org/en/stable/classes/class_displayserver.html; `packages/agent/templates/blank/project.godot`.
- **F24** Launcher icons: main ≥ 192×192 (Android 8 and earlier), adaptive foreground + background ≥ 432×432 (Android 8+), optional monochrome ≥ 432×432 (Android 13+); keep critical elements inside the 66 dp safe zone; missing icons fall back to the other icons, the project icon, then Godot's defaults; Godot makes the smaller variants (WebP). Docs (F1).
- **F25** Prebuilt (non-Gradle) APK flow: copies `custom_template/*` or `android_release.apk` / `android_debug.apk`; patches the binary manifest (package, version code/name, orientation, permissions) and string tables (app name); generates icons; stores the game as `assets/assets.sparsepck` (+ `assets/_cl_`); aligns entries in code (4 bytes; `.so` files to 16 KB, `PAGE_SIZE_KB = 16 * 1024`); signs with apksigner and verifies. Errors: "Release export template not found: \"%s\".", "Could not find template APK to export: \"%s\".", "Could not unzip temporary unaligned APK.", "Missing libraries in the export template for the selected architectures: %s.", "Could not export project files.". export_plugin.cpp, 4.7.2-stable.
- **F26** Signing: `package/signed` defaults true; `if (should_sign) { err = sign_apk(...) }` so an unsigned export skips apksigner; alignment "must be done before signing" and is done in-process; `sign_apk` runs apksigner with `--ks-pass pass:<password>` on the command line and signs in place; messages "Signing release APK...", "Verifying APK...", "Aligning APK..."; "'apksigner' could not be found..." and "All 'apksigner' tools ... failed to execute." are followed by "The resulting APK is unsigned." with the export still OK; "'apksigner' returned with error #%d" and "'apksigner' verification of APK failed." are errors; "AAB signing is not supported" on this path; the Gradle path gets `-Pperform_signing=<bool>`. export_plugin.cpp, 4.7.2-stable.
- **F27** Gradle flow: checks `android/.build_version` ("Android build version mismatch:\n| Template installed: %s\n| Requested version: %s"; missing: "Trying to build from a gradle built template, but no version info for it exists..."; "Android build template not installed in the project. Install it from the Project menu."); writes manifests and themes, puts the game in `src/main/assets` (APK) or `assetPackInstallTime/src/main/assets` (AAB); runs `<build dir>/gradlew` (`gradlew.bat` on Windows) with `validateJavaVersion [clean] assembleStandardRelease|bundleStandardRelease -p <build_path> -Paddons_directory= -Pexport_package_name= -Pexport_version_code= -Pexport_version_name= -Pexport_version_min_sdk= -Pexport_version_target_sdk= -Pexport_enabled_abis= -Pplugins_local_binaries= -Pplugins_remote_binaries= -Pplugins_maven_repos= -Pperform_zipalign=true -Pperform_signing= -Pcompress_native_libraries= [-Prelease_keystore_file= -Prelease_keystore_alias= -Prelease_keystore_password=]`, then `copyAndRenameBinary -Pexport_edition= -Pexport_build_type= -Pexport_format=aab|apk -Pexport_path=file:<dir> -Pexport_filename=`; no `--offline`, no `--no-daemon`. Errors: "Building of Android project failed, check output for the error:", "Unable to copy and rename export file:", "Could not export project files to gradle project.", "Unable to overwrite res/*.xml files with project name.". export_plugin.cpp, 4.7.2-stable.
- **F28** Godot prints Gradle's output only after Gradle finishes (`print_verbose` on success, an error with the output on failure); the Gradle path has no progress steps and the progress dialogs print nothing on stdout, so a headless export gives no live progress. export_plugin.cpp, editor/gui/progress_dialog.cpp, editor_node.cpp, 4.7.2-stable.
- **F29** "Export AAB" is valid only with "Use Gradle Build"; transparent background needs Gradle; a Gradle build installs an Android Java project into `res://android/build` and uses it as the export template on each export (reasons: AAB for Play, modify the project, add SDKs); folders whose name starts with an underscore are not included in the APK. https://docs.godotengine.org/en/stable/tutorials/export/android_gradle_build.html (4.7 docs, read 2026-10-18).
- **F30** A command-line Android export fails unless `rendering/textures/vram_compression/import_etc2_astc` is on or the host prefers ETC2/ASTC (a Linux x86_64 server prefers S3TC/BPTC): "ETC2/ASTC texture compression is required for Android export. In Project Settings, search for ETC2 in the search field, or enable Advanced Settings and go to Rendering > Textures > VRAM Compression to enable Import ETC2 ASTC." (printed only in command-line mode). The blank template does not set it. export_plugin.cpp and editor/import/resource_importer_texture_settings.cpp, 4.7.2-stable.
- **F31** Godot 4.7 (June 2026): "Use Gradle Build" lost its experimental warning (GH-119172); Play OBB support removed (GH-118283); splash screen configurable without Gradle; Perfetto is the default tracing tool in Android template builds. 16 KB page-size support landed in 4.5 (PR #106358, NDK r28b; 4.5 beta 1, 2025-06-18, which also bumped the minimum SDK to 24). https://godotengine.org/releases/4.7/, https://godotengine.org/article/dev-snapshot-godot-4-5-beta-1/, https://github.com/godotengine/godot/pull/106358 (read 2026-10-18).
- **F32** godot-ci (a widely used CI image) exports Android headlessly the same way: `openjdk-17-jdk-headless`, command-line tools with `yes | sdkmanager --licenses`, templates in `~/.local/share/godot/export_templates/<version>.stable`, an `editor_settings-<v>.tres` with `export/android/java_sdk_path`, `android_sdk_path` and the debug keystore fields, release keystore as base64 secrets, preset names case-sensitive. https://github.com/abarichello/godot-ci (Dockerfile read 2026-10-18).
- **F33** Google's own Godot guide: the build template lives in `android/build` (omit from version control); Gradle must be on for AAB or Android plugins; APK for adb testing, AAB for Play; "Google Play requires 64-bit architectures in submitted App Bundles. If you select the Armeabi-v7a architecture you must also select Arm64-v8a"; more ABIs mean a bigger file and a longer export; uncheck "Export With Debug" for release. https://developer.android.com/games/engines/godot/godot-export (updated 2026-02-26, read 2026-10-18).

## C. Signing tools and Play App Signing

- **F46** Android's command-line signing page: `keytool -genkey -v -keystore my-release-key.jks -keyalg RSA -keysize 2048 -validity 10000 -alias my-alias`; bundles: `jarsigner -keystore pathToKeystore app-release.aab keyAlias` and "You cannot use apksigner to sign your app bundle"; APKs: zipalign, then `apksigner sign --ks my-release-key.jks --out my-app-release.apk my-app-unsigned-aligned.apk`, then `apksigner verify`. https://developer.android.com/build/building-cmdline (updated 2026-02-26).
- **F47** apksigner: `--ks-pass` / `--key-pass` accept `pass:`, `env:`, `file:` and `stdin` (stdin is the default); without `--out` it signs in place; `apksigner verify --print-certs`; it must run after zipalign; in build-tools 24.0.3+. https://developer.android.com/tools/apksigner (updated 2026-03-05). zipalign: align before apksigner; `-P 16` aligns uncompressed `.so` files to 16 KiB pages (`zipalign -P 16 -f -v 4 in.apk out.apk`); check with `zipalign -c -P 16 4 app.apk`. https://developer.android.com/tools/zipalign (updated 2024-08-15).
- **F48** bundletool: `build-apks --bundle=... --output=... --mode=universal --ks=... --ks-pass=file:... --ks-key-alias=... --key-pass=file:...` makes one installable APK from an AAB (without `--ks` it uses a debug key); `dump manifest` and `dump config` read a bundle. https://developer.android.com/tools/bundletool (updated 2026-08-28).
- **F49** jarsigner (JDK 17): default SHA256withRSA for RSA keys up to 3072 bits; `-storepass[:env|:file]`, `-keypass[:env|:file]`; `-signedjar` names the output; signing an already signed JAR adds a second signer. https://docs.oracle.com/en/java/javase/17/docs/specs/man/jarsigner.html (read 2026-10-18).
- **F50** keytool (JDK 17): default keystore type PKCS12 since JDK 9; `-keysize` defaults to 2048 for RSA; `-validity` defaults to 90 days; `:env` / `:file` for passwords; "a password shouldn't be specified on a command line or in a script unless it is for testing"; `-list` prints the SHA-256 fingerprint; third-party tools expect storepass = keypass in PKCS12. https://docs.oracle.com/en/java/javase/17/docs/specs/man/keytool.html. PKCS12 default protection PBEWithHmacSHA256AndAES_256 since JDK 16 (backported to 11.0.12 and 8u301): https://bugs.openjdk.org/browse/JDK-8228481 (read 2026-10-18).
- **F51** Play App Signing: new apps are "automatically enrolled in quantum-ready, hybrid signing with Google-generated keys"; the developer keeps the upload key (a `.jks`/`.keystore`, "Must be an RSA key of 2048 bits or more"), Google holds the app signing key and signs the APKs delivered to devices; "your upload key and app signing key should be different"; a lost upload key: `keytool -export -rfc -keystore upload-keystore.jks -alias upload -file upload_certificate.pem`, then Play Console > Protected with Play > Play Store protection > Manage Play app signing > Upload key certificate > "Request upload key reset" (admin permission); "Resetting your upload key will not affect the app signing key"; a self-managed app signing key cannot be reset. The key must be valid past 22 October 2033, 25+ years recommended; "Configuring Play App Signing is required ... (except for apps created before August 2021)"; "most app stores (including the Google Play Store) do not accept apps signed with a debug certificate". A unique key per app is recommended. https://support.google.com/googleplay/android-developer/answer/9842756 (read 2026-10-18); https://developer.android.com/studio/publish/app-signing (updated 2026-03-06); https://developer.android.com/guide/app-bundle/faq; https://android-developers.googleblog.com/2021/06/the-future-of-android-app-bundles-is.html (2021-06-29).
- **F52** Community, not a Google page: Play refuses debuggable uploads with "You uploaded a debuggable APK or Android App Bundle. For security reasons you need to disable debugging before it can be published in Google Play." https://discussions.unity.com/t/you-uploaded-a-debuggable-apk-or-android-app-bundle-for-security-reasons-you-need-to-disable-debugging-before-it-can-be-published-in-google-play/226123 (read 2026-10-18).

## D. Google Play rules for a personal developer account

- **F53** "From August 2021, new apps are required to publish with the Android App Bundle on Google Play."; the compressed download size of the APKs needed to install must be ≤ 4 GB; AABs do not support OBB files. https://developer.android.com/guide/app-bundle (updated 2026-06-24).
- **F54** Target API: "Starting August 31, 2026, new apps and app updates must target Android 16 (API level 36) or higher"; existing apps must target 35+ to stay available to new users; "You will be able to request an extension to November 1, 2026". https://support.google.com/googleplay/android-developer/answer/11926878 (read 2026-10-18). Godot 4.7.2 targets 36 by default (F22).
- **F55** 16 KB pages: "all apps targeting Android 15 (API level 35) and higher must support 16 KB memory page sizes on 64-bit devices on Google Play. Starting February 1, 2027, if your app updates don't support 16 KB memory page sizes, you won't be able to release these updates."; native libs must be 16 KB ELF-aligned and packaged uncompressed (AGP ≥ 8.5.1); checks: `zipalign -v -c -P 16 4 app.apk`, `bundletool dump config --bundle=app.aab | grep alignment` (expects PAGE_ALIGNMENT_16K), `llvm-objdump -p lib.so | grep LOAD` (align 2**14). https://developer.android.com/guide/practices/page-sizes (updated 2026-10-16). Godot 4.3/4.4 templates were flagged by Play (forum reports); 4.7.2 is built with NDK r29 (F2).
- **F56** 64-bit: "for each native 32-bit architecture you support you must include the corresponding 64-bit architecture"; arm64-v8a only (Godot's default) complies. https://developer.android.com/games/optimize/64-bit (read 2026-10-18); F33.
- **F57** versionCode: a positive integer, each release greater than the last, a used value can't be re-uploaded, "The greatest value Google Play allows for versionCode is 2100000000"; versionName is free text shown to users. https://developer.android.com/studio/publish/versioning; https://support.google.com/googleplay/android-developer/answer/9859152 (read 2026-10-18).
- **F58** Application ID: "It must have at least two segments (one or more dots)", "Each segment must start with a letter", "All characters must be alphanumeric or an underscore", "Once you publish your app, you should never change the application ID"; Play: package names "are unique and permanent" and "can't be deleted or re-used". https://developer.android.com/build/configure-app-module; answer/9859152 (read 2026-10-18). Community-reported error text, no official page found: Play Console refuses "You need to use a different package name because 'com.example' is restricted." https://www.bestdevops.com/com-example-is-restricted-when-uploading-apk-to-play-store/.
- **F59** Developer account: 18 or older; US$25 one-time fee by credit/debit card (no prepaid cards); identity check with a government ID and a card in the legal name (fee not refunded if invalid); new personal accounts since early 2024 verify an Android device with the Play Console app; personal accounts created after 2023-11-13 must test before an app can be distributed. https://support.google.com/googleplay/android-developer/answer/6112435. Play Console requirements: legal name and address, contact email and phone (shown on Play where applicable), a payments profile; organisations need a D-U-N-S number; "Register your app package names via Play Console to comply with Android developer verification requirements". https://support.google.com/googleplay/android-developer/answer/10788890 (read 2026-10-18).
- **F60** Closed-test rule: "Google Play requires personal developer accounts created after November 13, 2023, to test their apps before those apps are eligible for distribution": "a minimum of 12 testers who have been opted in continuously for at least 14 days", consecutive; testers who leave early do not count; internal testing does not count; then Dashboard > "Apply for production" (three sections: about the closed test, about the app, production readiness); "Review usually takes seven days or less"; rejection reasons include fewer than 12 testers or insufficient engagement. https://support.google.com/googleplay/android-developer/answer/14151465 (read 2026-10-18). History (secondary source): 20 testers from 2023-11-13, lowered to 12 in December 2024: https://primetestlab.com/blog/google-play-changed-20-to-12-testers.
- **F61** Testing tracks: internal "up to 100 testers per app", new bundles "available to testers within minutes", updates not reviewed; closed tests: email lists ("up to 200 lists, and each list can contain up to 2,000 users") or Google Groups; open tests unlimited (a limit, if set, ≥ 1,000); testers need a Google account; "the test link can take several hours to become available"; "The opt-in link displays only when an app status is 'Published'". https://support.google.com/googleplay/android-developer/answer/9845334 (read 2026-10-18). ESTIMATE: the opt-in URL has the form `https://play.google.com/apps/testing/<package name>` (what Console and tester guides show; the exact help text was not retrievable).
- **F62** Creating the app: default language, app name ("30 characters", changeable later), app or game, free or paid, contact email ("A contact email address is required"), the Developer Program Policies and US export laws, the Play App Signing Terms of Service, then "Create app"; listing text limits: app name 30, short description 80, full description 4,000 characters. answer/9859152 (read 2026-10-18).
- **F63** Store graphics: app icon 512×512, "32-bit PNG (with alpha)", ≤ 1024 KB, required; feature graphic 1024×500, "JPEG or 24-bit PNG (no alpha)", required; screenshots JPEG or 24-bit PNG, each side 320-3840 px, "The longer side can't be more than twice the shorter side", up to 8 per device type, at least 2 to publish; games recommended ≥ 3 at 16:9 (≥ 1920×1080) or 9:16 (≥ 1080×1920); preview video optional (YouTube). https://support.google.com/googleplay/android-developer/answer/9866151 (read 2026-10-18). The check's phone shots are 432×936 (ratio 2.17, `packages/agent/tools/check.mjs`), so they would be refused.
- **F64** App content declarations (Policy > App content): privacy policy ("available on an active URL, applies to your app, and specifically covers user privacy"), ads, app access (sign-in details), target audience and content (age groups; children in scope = Families policy; child-appealing imagery "may impact Google Play's assessment of your declared target audience"), sensitive permissions, content rating (IARC questionnaire; "Unrated apps may be removed"), Data safety (every published app including closed and open tracks, internal-only exempt since 2022-10-24; an app that collects nothing still fills it; a privacy policy link "is required to complete the Data safety form"; CSV export/import), Financial features and Health apps ("none" must be certified by everyone), Government apps, Advertising ID (apps using it declare `com.google.android.gms.permission.AD_ID`; a Godot game without an ads SDK has no such permission). https://support.google.com/googleplay/android-developer/answer/9859455, .../17118006, .../10787469, .../9859655, .../9893335, .../13849271, .../14738291, .../9514050, .../6048248 (all read 2026-10-18).

- **F67** Android developer verification: "Effective September 30, 2026, protections begin for users installing apps from participating stores in select regions" (Brazil, Indonesia, Singapore, Thailand; certified devices on Android 7+), "expanded globally for all apps on certified Android devices in 2027"; registration = a verifiable link between the package name and the signing key; "Google Play automatically registers 99% of apps"; Play App Signing apps are registered automatically and Play Console can register outside-Play apps and keys; unregistered apps install only through ADB or the "advanced flow" (a one-time 24 h wait); FAQ: direct sideloading "won't apply to your app yet"; free "limited distribution" accounts cover 20 devices. https://developer.android.com/developer-verification (+ /guides, /guides/faq, /guides/limited-distribution, updated 2026-09-30); https://android-developers.googleblog.com/2026/03/android-developer-verification-rolling-out-to-all-developers.html (2026-03-30).
